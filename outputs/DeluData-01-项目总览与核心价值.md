# DeluData：项目总览与核心价值

返回：[[DeluData-项目知识索引]]

## 一句话定位

DeluData 是面向企业数据和知识资产的多租户 AI 操作平台：用户用自然语言提出业务问题，系统在权限边界内自动选择数据库、知识库、Wiki、文件、图表或 Office 能力，并给出带证据和可复用产物的答案。

## 要解决的问题

企业数据工作常被拆成互不连通的链路：业务人员不会写 SQL；知识散落在文档；指标口径缺少统一语义；图表和 Office 文件依赖人工整理；权限又分散在数据库、组织、文档和应用层。DeluData 的目标不是增加一个聊天框，而是把这些链路组织成可规划、可审计、可恢复的任务执行系统。

## 核心能力

### 自然语言问数

- 识别业务表、字段、指标和时间范围。
- 在数据库白名单与只读校验后生成、执行 SQL。
- 把结果保存为会话级结构化数据，供追问、图表和 Office 继续使用。
- 支持直连模式和 Planner 多步骤模式。

### 企业知识问答

- 解析 PDF、Word 和文本，执行 OCR、分块和向量化。
- 结合向量检索、BM25、中文分词、重排和上下文扩展。
- 输出引用、页码、图片和结构化证据。
- 通过 Wiki-First 优先使用治理后的知识，缺失时回退原始 RAG。

### 数据产品生成

- Chart Worker 生成可视化产物。
- Office Worker 创建 Word、Excel 或填充模板。
- Inspect File 把上传文件转为 Planner 可理解的数据来源。
- 产物通过 SSE 和沙箱 Artifact 接口返回前端。

### 可信语义治理

- 建立 Schema 基线、业务语义、指标、关系、Join 和访问策略。
- 从数据画像、查询历史和人工反馈采集证据。
- 生成候选资产，经观察、评分、人工决策或安全自动应用后进入可信层。
- Trusted 模式强调缺失即澄清，不允许用猜测掩盖语义空洞。

### 展厅体验

- 博物馆扩展场景受 Workspace Feature Flag 控制。
- Kiosk 是独立产品面，围绕设备激活、访客画像、语音问答、答题和奖励运行。

## 核心设计思想

### 编排与能力分离

Supervisor 管理状态与流程；Worker 负责领域任务；Skill/Tool 封装底层能力。SQL、RAG、图表和 Office 可以分别演进，不必堆在一个巨型 Agent 中。

### 状态持久化优先

会话进入 MySQL Checkpointer，而不是依赖进程内存。用户可以确认计划、刷新页面、恢复中断，并在后续轮次继续使用上一轮数据。

### 证据优先于模型自信

数据库查询依赖受控 Schema 和语义资产；知识回答携带引用；语义治理使用多来源证据。可信度来自可验证链路，而不是 LLM 的肯定语气。

### 多租户隔离是基础能力

Workspace 贯穿认证、数据库、文档检索、文件存储、设备和后台任务，是系统的第一安全边界。

## 当前演进方向

1. Authorization V2：用户、角色、部门和访问策略向统一授权中心收敛。
2. Semantic Trust Foundation：建立可信语义基线与严格运行模式。
3. Evidence Governance：形成证据采集、候选生成、决策与反馈闭环。
4. Knowledge MCP：把内部知识能力开放给其他 Agent。
5. 进程隔离：入库、Wiki 编译和自动治理逐步迁出 Web 进程。

## 判断改动是否符合方向

- 是否保持 Workspace 与权限隔离？
- 是否让数据、证据和产物流向更清晰？
- 是否保留可恢复、可审计状态？
- 是否增加对应测试和运行诊断？
