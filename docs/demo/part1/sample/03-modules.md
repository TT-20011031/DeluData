# DeluData 核心模块

本文档汇总三大核心模块的对外契约与默认参数。**所有数字均为出厂默认值**，可在 admin 后台覆盖。

---

## RAG 模块

### 定义

[[rag]] 是 DeluData 的多模态文档检索模块。它把上传的 PDF / Word / Excel / Markdown / 纯文本统一拆为 [[chunk]]，写入向量库，并在查询时执行混合检索 + 重排序。

### 默认参数

- 默认切片大小：**800 字**（按语义切分，尾句优先收口）
- 默认切片重叠：**80 字**
- Embedding 维度：**1024 维**
- 默认 Top-K（召回阶段）：**20**
- 默认 Top-N（重排序后）：**6**
- 单次查询最大耗时上限：**8 秒**

### 检索五步

1. **语义切分** — 基于 Embedding 相似度的智能分块，避免硬切断句子。
2. **混合检索** — Dense（向量）与 Sparse（BM25）双路召回各取 Top-20。
3. **重排序** — Cross-Encoder 精排，输出 Top-6。
4. **上下文扩展** — 父子索引补充前后切片，提升上下文完整度。
5. **图片关联** — VLM 生成的图片描述与切片同库，可"以图搜文"。

### 与 Wiki 的关系

[[rag]] 与 [[wiki]] 共享原始文档：每个 [[chunk]] 都可以被 [[entity-page]] 通过出处溯源关联回去。这意味着同一份原文同时支撑两条路径——切片用于"原文摘录"，实体页用于"是什么"。

---

## Wiki 模块

### 定义

[[wiki]] 是 DeluData 的实体知识层（Karpathy LLM Wiki 模式）。它通过 LLM 从原始文档中抽取**核心实体**，每个实体生成一张 [[entity-page]]，自带双向链接、出处溯源与修订历史。

### 默认参数

- 单工作区最大实体页数：**500**
- 单页最大出链数：**50**
- 单实体页最大字数：**12000**
- INDEX 摘要截断长度：**80 字**
- Wiki 编译并发度：**4**

### 编译六步

1. **候选抽取** — LLM 读文档摘要 + 切片标题，列出候选实体。
2. **slug 对齐** — 按 slug + alias 在已有 wiki_pages 中查重，决定 create / update。
3. **增量分类** — 新建 / 更新 / 标记冲突三类操作意图分别落库。
4. **双向链接** — 解析 markdown 中 `[[xxx]]` 标记，写入 wiki_links。
5. **出处溯源** — 每条事实绑定 [[chunk]] ID 写入 wiki_page_sources。
6. **修订历史** — 每次编译都写一条 wiki_revisions，便于 diff。

### 三联视图

每张 [[entity-page]] 在前端呈现三块：

- **正文** — markdown 渲染
- **反向链接** — 哪些实体页引用了我（自动维护）
- **出处证据** — 来自哪些原始文档的哪些 [[chunk]]（可点击溯源）

## Text-to-SQL 模块

### 定义

[[text-to-sql]] 是 DeluData 的自然语言转 SQL 模块。它接收业务自然语言（"本季度各部门销售额对比"），输出可执行 SQL，并在执行前后分别经过两道安全围栏：**语义防火墙 + 执行防火墙**。

### 默认参数

- 单查询最长 SQL 长度：**4000 字符**
- 默认执行超时：**30 秒**
- 默认结果集行数上限：**5000 行**
- 多表 JOIN 上限：**5 张表**

### 安全围栏

- **语义防火墙** — SQL 生成阶段就拒绝越权查询、危险关键词（DROP / TRUNCATE / ALTER）。
- **执行防火墙** — 实际执行阶段强制只读连接，并对结果集行数 / 时延做硬限。

---

## 三模块的协同

一次复杂的用户问题可能同时触发多模块：例如"对比一下上月销售额并解释下绿色大额订单的合规要点"，会先由 Supervisor 拆为两个子任务，分别走 [[text-to-sql]] 和 [[knowledge-router]]，再由 Synthesizer 把表格 + 实体页解释合并为一段回答 + 一组 citation。
