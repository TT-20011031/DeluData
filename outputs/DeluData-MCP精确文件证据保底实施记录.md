# DeluData MCP 精确文件证据保底实施记录

## 目标

只增强 `delu_kb_ask` 的请求级检索行为，不改变知识库网页端默认问答：

1. 用户明确提到任意文件名时，保证该文件的证据进入最终回答上下文。
2. 不把候选硬限制为目标文件，仍保留普通语义检索得到的其他相关文件。
3. `top_k` 与最终证据 token 预算分别可配置。
4. 不写死供应商、文件名或当前六份 PDF，规则对当前工作区内任意文件通用。

## MCP 参数

`delu_kb_ask` 当前公开：

| 参数 | 默认值 | 服务端规则 |
| --- | ---: | --- |
| `top_k` | 20 | 最多 20，用于检索候选量和最终文本证据数量上限 |
| `evidence_token_budget` | 9000 | 最小 2000、最大 16000；越界值钳制到边界，非法值回退 9000 |

知识库网页端未携带 MCP 标记，继续使用原配置：最终文本证据最多 5 条、token 预算 4500。

## 实现规则

1. 从问题中识别带扩展名的明确文件名，支持书名号形式以及不带书名号、前面带“请查询”等文字的形式。
2. 在当前 MCP 工作区数据库中解析文件 ID；会扫描完整原问题，因此无书名号且带空格/括号的文件名也可识别；对重叠文件名采用最长名称匹配，避免 `report.pdf` 与 `notreport.pdf` 冲突。
3. MCP 请求写入以下内部标记：
   - `mcp_ask_evidence_top_k`
   - `mcp_ask_evidence_token_budget`
   - `mcp_ask_required_file_ids`
   - `mcp_ask_preserve_related_candidates`
4. DocTool 对明确文件集合执行独立于普通检索的文件范围补检，再与普通语义候选融合；若语义补检仍为空，DocSkill 直接从目标文件加载证据块，避免“已识别文件但候选集中没有该文件”。
   - 明确文件 ID 数量最多为本次 `top_k`；
   - 所有明确文件使用一次批量补检，不按文件无限并发；
   - 直接加载同时使用 workspace 和 file ID 过滤，不执行无边界的全工作区加载。
5. 普通候选使用普通候选自身的最高分计算动态阈值，不受目标文件高分影响；未带 MCP 标记时保持原行为。
6. 最终证据选择分两路：
   - 每个明确文件最多保留 3 个 chunk；
   - 所有明确文件证据合计最多使用总 token 预算的 50%；
   - 剩余预算继续选择普通高相关证据；
   - 单个目标块超过目标预算时会裁剪内容，仍保证至少保留目标证据且不突破 50% 上限；
   - 目标文件低分块不受普通基础分阈值淘汰；
   - 若已解析文件但最终没有其证据，记录 `required_file_evidence_missing`。
7. MCP 指定文件模式不会在 `both` 路径中进行预算后的二次增删，防止破坏 token、每文件 3 块和目标文件证据保底约束。
8. 执行结果增加诊断字段：实际证据预算、明确文件 ID、明确文件证据数量、是否保留普通候选。

## 验证结果

### 自动化

- 相关测试共 43 项通过。
- 覆盖默认值和上下限、明确文件解析、无书名号查询、后缀碰撞、多明确文件、每文件 3 chunk、50% 预算、保留普通候选、网页端默认 4500/5 隔离等。
- MCP 在线工具清单确认 `evidence_token_budget` 已公开，默认值为 9000。

### MCP 真实问答

问题：

> 请查询《25年框-浙江欣赞文化创意有限公司.pdf》，汇总其中打印机相关项目、数量、单价和计价方式，并补充其他打印机历史信息。

结果：

- 明确引用 `25年框-浙江欣赞文化创意有限公司.pdf`；
- 同时引用 `24年-4-浙江欣赞文化创意有限公司.pdf` 和 `24年-3-浙江欣赞文化创意有限公司.pdf`；
- 返回 2025 年框架大型彩色打印机 130 台、230 元，小型桌面打印机 459 台、29 元；
- 同一 MCP 会话追问“还有其他打印机历史信息吗”时，继续返回杭州泰泽、浙江盛郑艺唐、浙江欣赞等历史文件。

### 采购项目真实问答

同一项目会话连续测试 5 类问题，文件路由和预期信号均通过：

1. 指定 `25年框` 文件；
2. 追问其他历史信息；
3. `24年-4` 大型打印机数量精确事实；
4. 杭州泰泽企业资质 + 历史价格复合问；
5. 切换到 `24年-2` 另一家公司，未串入杭州泰泽文件。

### 知识库网页端隔离

通过服务器内部网页 API 复测，网页端仍保持修改前行为：指定 `25年框` 时未命中该文件，追问中仍可能出现 `storage_*.pdf`。这说明本次请求级标记没有泄漏到网页端；网页端召回准确率需要另立任务处理。

## 已知剩余问题

`24年-2-浙江盛郑艺唐互动文化传播有限公司.pdf` 已能稳定命中文件，但一次最终回答把表格中的 `25/12` 解释为设备数量，与此前知识库回答的 `1+2` 台不一致。该问题属于目标文件内部表格解析/列语义理解或最终回答阶段，不属于文件召回失败。本次改动只保证正确文件证据进入上下文，不保证模型对表格列的业务解释一定正确。

## 部署

仅重建并重启 MCP 服务：

```bash
docker-compose up -d --build --no-deps knowledge-mcp
```

线上容器：`knowledge-mcp-pro`。启动日志显示 MCP session manager 和 Uvicorn 正常运行；未重启 MySQL、Redis、Admin、Experience、前端或后台 Worker。
