# DeluData 知识中枢升级（M1–M4）

> 从"一堆原始文档 + 切片检索"升级为"实体页 + 智能路由 + 治理回路"，让概念性问答精准命中、知识资产可观测可治理。

## M1 — 知识底座

- **原本**：知识库只有原始文档与切片，问"X 是什么"要在长文里翻原文，答案散落且无追溯。
- **现在**：每个核心实体有一张独立的 **Wiki 实体页**，自带出处、双向链接、修订历史；管理员可一键编译，普通用户可直接浏览。
- **技术亮点**：LLM 候选抽取 + slug 对齐去重 + 切片级出处溯源；编译过程不持事务，写入由 service 层原子提交。

## M2 — 健康巡检

- **原本**：编译产出无人审查，孤儿页、断链、未决冲突悄悄堆积，越长越乱。
- **现在**：管理员一键 Lint，输出 **孤儿页 / 断链 / 未决冲突 / 过期** 四类清单化报告。
- **技术亮点**：规则优先零 LLM 成本，仅在需要修复建议时按需调用 LLM。

## M3 — 智能路由（Wiki-First）

- **原本**：所有问题统一走 RAG 切片检索，"是什么"和"原文摘录"混在一条链路上，又慢又模糊。
- **现在**：**KnowledgeRouter** 在检索前判定走 `wiki / rag / both`；常见关键词命中规则即出结果，模糊问题才用快模型分类；前端 Scope 选择器可直接锁定 Wiki 域或实体页；管理员能看到 7/14/30 天的路由健康度卡片。
- **技术亮点**：规则 + LLM + Fallback 三段式路由，每次决策落库可观测；显式 Scope 直接零 LLM。

## M4 — 治理回路

- **原本**：Wiki Gap（"这次答得不全因为没这页"）只能人工补；批量编译还可能爆配额拖垮数据库。
- **现在**：检测到 Gap **自动入队**后台编译，下次提问就有答；编译时实时受 **每工作区页数 / 单页出链** 配额约束；新增 `/api/wiki/quota` + 健康度卡片配额条，接近上限自动告警。
- **技术亮点**：Fire-and-forget 入队不打扰主问答；双层配额防御——运行时截断 + 观测态告警。

## 一句话证据

- 4 个里程碑落地，Wiki 子系统 6 张表，新增 3 个治理 API（`/lint`、`/metrics/route`、`/quota`）。
- Wiki/路由相关后端单测 **118 / 118 通过，零回归**。
- 关键开关 `wiki.first_enabled=false` 时全部改动旁路退化，可平滑灰度上线。
