# 可信语义治理底座

## 升级

1. 备份 DeluData 配置数据库。
2. 在 MySQL 8 上执行 `backend/migrations/add_semantic_trust_foundation.sql`。
3. 重启 Admin Backend；启动时 `Base.metadata.create_all` 会补建新增表，但已有表字段仍以迁移脚本为准。
4. 打开语义治理控制台，运行一次“扫描 Diff”并应用，建立首个 Schema 基线。

迁移将现有已确认对象视为可信人工资产。后续扫描只更新物理元数据，不覆盖业务名、说明、同义词、公式、状态或权限。

## 管理员流程

1. 点击“扫描 Diff”，检查新增、修改、移除和受影响资产。
2. 点击“原子应用全部变化”。预览后数据库若再次变化，系统拒绝应用并要求重新扫描。
3. 处理标记为“过期”或“失联”的对象；在完成业务复核前这些对象不可问数。
4. 使用“可信诊断”验证重点问题，不执行 SQL。
5. 先切换 Shadow 并观察新旧链路对照；确认结构和安全就绪后，再由管理员切换 Trusted。

## 运行模式

- `disabled`：只执行旧 XiYan/黄金 SQL 链路。
- `shadow`：新旧链路同步并行执行，始终把旧链路结果返回用户；数据库负载可能接近翻倍。
- `trusted`：语义链路为权威链路。语义缺失、需要澄清和 Join 歧义均不会回退猜测。

切换 Trusted 的硬条件是存在已应用 Schema 基线且配置只读数据库账号。语义覆盖不足会显示警告，但最终由管理员决定是否晋级。
